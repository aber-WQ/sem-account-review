# 数据工具契约与使用边界

`scripts/sem_data.py` 是 Python 3.10+ 标准库工具，读取本地文件，不联网、不访问账户、不执行投放修改。它负责检查和计算可核对的事实，不负责网站研究、意图识别、策略判断或最终 Excel 排版。不能把脚本成功运行当作业务结论已验证。

## 1. 命令

在 Skill 目录执行，`python` 可替换为当前环境实际解释器路径：

```text
python scripts/sem_data.py inspect "report.csv" --samples 3 --output "inspection.json"
python scripts/sem_data.py inspect "report.xlsx" --sheet "搜索词" --header-row 1
python scripts/sem_data.py prepare "report.csv" --mapping "mapping.json" --periods "periods.json" --output "facts.json"
python -m unittest discover -s tests -v
```

输出使用 UTF-8 JSON。成功返回码为 0；错误返回码为 2，stderr 包含 JSON 错误说明。`--output` 必须是尚不存在的文件，防止覆盖来源或旧分析；父目录需先创建。CSV 默认 UTF-8（允许 BOM），TSV 默认制表符。其他编码需在 inspect 指定 `--encoding gb18030` 或 mapping 中指定 `encoding`。inspect 支持 `--delimiter`、`--header-row`；prepare 从 mapping 读取这些设置。不要自动尝试多种编码后把乱码当作正常文本。

`mapping.json`和本节的数组式`periods.json`是AI根据实际报表与本次运行配置生成的脚本参数，不要求使用者填写；不能将`assets/run-config-template.json`直接当这两个文件传入。每份来源使用明确的字段映射，范围和来源记录保存在本次输出目录。

## 2. 显式映射

本文统一称广告组层级为“推广组”；不同平台的报表可能标为“单元”或“广告组”。映射中的源字段值必须填写当前报表实际表头，示例名称不能直接照抄。

先检查原表，确认每列业务含义，再写 mapping。禁止以“转化”字样相似为理由把不同转化事件互换。示例：

```json
{
  "sheet": "搜索词",
  "header_row": 1,
  "grain": "search_relation",
  "columns": {
    "date": "日期",
    "campaign_id": "计划ID",
    "campaign": "计划",
    "ad_group_id": "单元ID",
    "ad_group": "单元",
    "keyword_id": "关键词ID",
    "keyword": "关键词",
    "search_term": "搜索词",
    "actual_match": "实际匹配",
    "trigger_type": "来源",
    "cost": "消费",
    "impressions": "展示",
    "clicks": "点击",
    "conversions": "表单数"
  },
  "constants": {
    "account_id": "account_01",
    "currency": "CNY",
    "conversion_event": "有效提交表单"
  },
  "field_status": {
    "account_id": "confirmed",
    "currency": "confirmed",
    "conversion_event": "confirmed"
  }
}
```

上述名称仅示例，必须替换成实际存在的表头；无某列则删掉对应映射。一个字段只能来自列或常量之一，一列不能映射成两个不同含义。至少映射一项数值指标。消费、展示、点击、转化均只能来自原始列，不能通过常量制造。

- `search_relation`：每行必须有计划、单元及搜索词；关键词ID、关键词均为空时保留为 `non_keyword_traffic`，不虚构关键词。
- `aggregate`：适用于只有账户/计划/关键词汇总的报告；可以计算现有指标，不能因此生成全量搜索词语义、搜索词关系或否词。
- 计划、单元优先用平台ID，缺失可用名称。关键词有ID时，以账户+关键词ID建立稳定对象；真实关系键为账户+历史计划/单元+关键词对象+搜索词原文。实际匹配和触发来源保留在事实维度，不额外拆散这一真实关系；避免把同一关系内有转化和无转化的触发明细分开后夸大零转化关系消费。同一关键词移组后对象相同、关系不同。无关键词ID时，备用对象身份使用账户+计划+单元+关键词原文+匹配，可能因匹配不同分成不同对象，明确无法可靠跟踪改名/移组。非关键词流量对象仍按来源中实际可见的触发机制区分。
- `actual_match` 指这份导出中已确认含义的匹配字段，不得把当前配置、历史触发机制混成一个事实。无法确认的字段先保留在原文件，映射说明记录缺口。
- 消费需要明确币种，转化需要明确事件，所有行需要账户作用域。缺平台账户ID但来源确认唯一时，可显式设置 `account_id: "source_scope:本次文件组"` 并标 `field_status.account_id: "internal_scope"`。这只是内部隔离标识，不是假造平台ID。
- 币种未知可显式填写 `currency: "unknown"`、`field_status.currency: "unknown"`；此时只保留源金额，不称为人民币/美元、不跨来源或币种合并。转化定义未核实时，可保留真实导出列标签，例如 `conversion_event: "平台报告转化_定义待核验"`，并标 `field_status.conversion_event: "unknown"`。仍可计算报告口径比率，但不能声称已确认是有效线索、订单或特定目标事件。
- 混合账户、币种、事件时映射相应列，不用单个常量掩盖差异。按这三项和期间分别汇总；不生成跨分区总计。特别注意多事件报告可能重复展示相同消费/点击，不能把不同事件行的流量指标再相加。
- 多层级表或带小计、总计的表，先由分析者确认原始粒度。脚本不自动去重、不自动删小计。如果确认为导出总计，可以设置 `exclude_rows: [52]` 和 `exclude_reason: "第52行为人工核对的导出合计"`。排除记录随结果保留。
- 空白维度保持缺失；关键词和搜索词只在全文为空白时视为缺失，其他情况保留原文，包括首尾空格、大小写和换行，不默认清洗后合并。需要格式归一化时，应另建规范值及原文映射、记录转换日志，经确认后再使用，不能覆盖原始关系。空白指标不是0。不自动解释逗号分隔千位、币种符号、百分号、括号负数等。先依据明确口径在派生文件规范化并保留转换说明。当前工具不支持负消费/退款调整；应单独核算并对账，不能直接删除负数记录。

## 3. 期间

`periods.json`：

```json
[
  {"id": "W1", "start": "2026-10-05", "end": "2026-10-11"},
  {"id": "W2", "start": "2026-10-12", "end": "2026-10-18"}
]
```

期间起止均包含；不能重叠。日期默认要求 `YYYY-MM-DD`。其他格式须明确 `date_format`（Python `strptime` 格式，例如 `%Y/%m/%d`）；有时间和时区时必须明确日界线及格式，不自动按本机时区截日期。日期在范围外时出错，不悄悄忽略。

没有逐行日期、但已明确整份报告覆盖 W2 时，删掉 `columns.date`，设置 `constants.period: "W2"`，并在运行记录保存报告期间证据。脚本只将该文件视为这一整期，不拆成两周。两份周报分别运行、分别留来源，再由明确合并流程衔接；本工具没有多文件自动合并功能。没有记录的期间不会补0，也不能仅依据文件名推测报告期间。

## 4. 输入文件的实际支持范围

- CSV/TSV：平面表，一行表头，物理行号保留；包含换行的引号字段以起始物理行作来源。
- XLSX：读取指定工作表，支持共享字符串、内联字符串、稀疏单元格、标准数值、文本ID、1900/1904日期系统和常见日期格式。多个Sheet时必须指定Sheet。
- 公式只读取已保存的缓存值，不重新计算；缓存可能陈旧，inspect总会提示。映射字段若公式无缓存或为Excel错误值，prepare失败，禁止吞为0。请使用Excel重算另存或取得原始导出再核验。
- 文本ID完整保留，包括前导0和长ID。数值型ID按Excel实际保存值读取并警告显示补零无法恢复；超过15位的数值型ID拒绝作为身份，需重新导出文本ID。已被Excel截断的数字无法恢复。
- 常用内置日期格式自动读取；自定义或区域相关日期/时间格式不猜。已确认对应列确为Excel日期序列时可显式设置 `date_encoding: "excel_serial"`；也可导出ISO文本日期。时间序列不是报告日期，不能仅为通过检查添加该设置。
- 合并单元格不向下填充；隐藏行和过滤掉的行仍全部读取并提示。不要把“视觉上只显示的行”当作实际输入范围。
- 不支持`.xls`、`.xlsb`、加密文件、任意非标准OOXML、图片表格、透视表计算或网络链接刷新；复杂布局先另存为可核对的平面CSV。脚本不宣称覆盖所有广告平台的导出格式。

## 5. 输出与对账

`inspect` 输出：文件/Sheet、可用Sheet、物理非空数据行数、列名、小样本、公式/格式等警告。样本仅用于字段辨认，不代表全量语义已分析。

`prepare` 输出主要字段：

| 字段 | 含义 |
|---|---|
| `source` | 原始文件、Sheet、输入/保留/排除行数与排除理由 |
| `mapping`、`mapping_fingerprint`、`periods` | 本次显式映射、源列映射指纹及期间，便于复核 |
| `facts` | 每个保留原始行一条事实；包括来源、原值、规范维度、对象ID、关系ID、指标 |
| `summaries.period` | 期间×账户×币种×事件汇总 |
| `summaries.object` | 上述分区内按对象汇总 |
| `summaries.relation` | 上述分区内按搜索词关系汇总；aggregate模式为空 |
| `warnings` | 可追溯的数据限制；必须进入分析检查，不能忽略 |
| `capabilities` | 明确本工具没有语义分类、公式重算、全量账户资产证明能力 |

所有fact有 `source_refs: [{file, sheet, row}]`，汇总保留贡献行列表。`fact_id`由文件/Sheet/物理行、期间和源列映射指纹共同生成；相同来源、期间及映射重跑时稳定，JSON中映射键排列顺序不影响ID。同一双周宽表分别映射W1/W2源列时不会撞ID。这不证明不同映射或多个文件之间没有重叠，也不能替代业务粒度检查。重复数据行原样保留，避免把合法重复粒度误删；在批量接入多个导出时，分析者仍必须检查重叠日期、快照、层级与重复导出。

数值用Decimal计算；`metric_decimal`及汇总`exact_decimal`保留精确十进制字符串，JSON `value`用于方便消费。这里的精确指读取并保留文件实际存储的数值；XLSX本身可能已有浮点尾差，不代表金额具有那些小数位的业务精度。高精度复核使用十进制字符串，最终展示按已确认的币种/原报表精度四舍五入，不把浮点显示误差当源差异。

每项汇总指标包含：`value`（只有全部来源行该指标完整时才有值）、`observed_sum`（已观察值的局部合计）、`complete`、`missing_rows`。缺失部分不能用局部合计冒充完整值。

CTR=总点击/总展示、CPC=总消费/总点击、CVR=总转化/总点击、CPA=总消费/总转化；不是逐行比率平均值。CTR/CVR为小数比例（0.1=10%）。分子或分母数据不全时比率为null，原因`incomplete_inputs`；分母为0时为null并标`zero_clicks`、`zero_impressions`或`zero_conversions`。0转化CPA绝不写0。

工具输出不能替代以下检查：源报告是否为同一粒度、是否完整、事件是否可比、是否存在转化延迟、网站事实与内部规则是否可信、否词覆盖是否符合平台规则、执行动作是否作用于真实对象。最终9表须以规范事实和经过审查的判断台账生成，并另行完成跨表对账。
